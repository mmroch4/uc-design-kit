  3. Reading the input

    Let's start by implementing the read() function. You should start by putting the input examples on files (e.g. ip097_input01.txt and ip097_input02.txt) so that you can easily call them afterwards to test your code.

    To get you started we will give you the code for this one:

    def read():
    global r, k, line
    r, k = map(int, input().split())
    line = input()

    If you put this code, not only will the input be read to variables r, k and line, but they will also be available outside of the function. You could as well return the 3 values (e.g. as a tuple) but here we want to also show how you could have a global variable that does not need to be passed around all the functions - and in this case this is the global data of the problem.

    Don't forget to test that you are reading correctly. To do that, put the following code outside of all functions (in the bottom), right after you call read():

    print(f'{r=}, {k=}, {line=}')

    If you call your program and feed it with the input (python ip097_skeleton.py < ip097_input01.txt) you should be able to see the following output, signaling it it is correct:

    r=128, k=5, line='#############'

    Don't forget to also do that with the second example input to see if everything seems ok

  4. Converting an integer rule to its individual bits:

    Let's start implementing the small functions, beginning with rule_to_8bits.

    This should convert the integer representing a rule to its individual bits (that we will use afterwards). When called with the following tester code:

    print(f'{rule_to_8bits(30)=}')
print(f'{rule_to_8bits(128)=}')
print(f'{rule_to_8bits(42)=}')

    It should produce the following output (notice they come reversed in relation to the table in the problem statement - this is not a problem, as we will see):

    rule_to_8bits(30)=[0, 1, 1, 1, 1, 0, 0, 0]
rule_to_8bits(128)=[0, 0, 0, 0, 0, 0, 0, 1]
rule_to_8bits(42)=[0, 1, 0, 1, 0, 1, 0, 0]
  5. Converting a char triplet:

    Now let's proceed with str_to_number.

    This function should convert a triplet of chars '.' and '#' and return a number representing the positoin of the triplet if interpreted as a binary string (with zero being '.' and one being '#'). Test the code with: 

    print(f'{str_to_number("...")=}')
print(f'{str_to_number("..#")=}')
print(f'{str_to_number(".#.")=}')

print(f'{str_to_number("##.")=}')
print(f'{str_to_number("###")=}')

    Which should produce (notice how they correspond to the position in the table of the problem statement... and to the positions of the bits we produced with rule_to_8bits):

str_to_number("..#")=1
str_to_number(".#.")=2
str_to_number(".##")=3
str_to_number("#..")=4
str_to_number("#.#")=5

    def calculate(rules, triplet):

  7. Generating a new line:

    Now onto generating a new line with function create. You just need to traverse the current line and generate a new line for each triplet. How to deal with the special case of the first and last character of the line not having a the entire triplet? Here are two options:

    • Use sentinels: add to each line a '.' at the start and at the end: this means that now every "main" character will always have some character to the left or to the right
    • Treat the first and last char differently and add manually a '.' to the start or end of the triplet

Can you try to organize the code yourself? And can you generalize so that you don't end up repeating code for all the eight directions? Try first to think on how to do it and use structured programming to divide the task into small simple blocks that you can incrementally develop and test.

If you are stuck or want to see a possible approach, the hints sections provides a possible code organization and generalization.

Hints

- As before, divide into reading and solving

- We suggest you convert to a list of lists (our usual matrix representation) while reading (and you can also use that format for the output)

- For solving, try each cell as a possible start for each word

- To test a word on a given position, iterate through all its characters and keep track of the current cell position to see if it is a match

- To generalize, use increments that define what a direction is, as shown in the lectures. For instance:

  • north can be defined as incrementing -1 to the current y, incrementing 0 to the current x and as the string "N"
  • northeast can be defined as incrementing -1 to the current y, incrementing +1 to the current x and as the string "NW"
  • ...

You can just initialize one or more variables that encapsulate all the eight directions!

- Be careful to not test positions outside of the grid

- Initialize an "empty" output grid just with dots and each time you discover a word, you can just add it to the output using the same generalized direction idea.

Hints

- On each cell, like in game of life, count the bomb in neighbor cells and act accordingly:

  • It it is a bomb, just reveal it
  • It if has neighbor bombs, just reveal the number of bombs
  • If it is empty and has no neighbor bomb, reveal a '.' and recursivelly call again the same function of all neighbor cells
  • You can do better than 8 recursive calls on the recursive part, using two cycles to go through all neighbors
