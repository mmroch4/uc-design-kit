Personalizar

Visão geral

O kit pode ser adaptado em cinco níveis, do mais simples (mudar um campo no course.js) ao mais livre (escrever HTML próprio). Cada nível dá mais controlo e pede mais manutenção. Usa-se sempre o nível mais baixo que resolve o problema.

Os cinco níveis

  1. 0 course.jsCor, logótipo, páginas, línguas.
  2. 1 Tokens no theme.cssCores, cantos, tipo de letra.
  3. 2 CSS livre no theme.cssRegras sobre as classes estáveis e classes próprias.
  4. 3 Componentes própriosUm elemento novo em extensions/.
  5. 4 HTML livreQualquer HTML dentro das páginas.

Os níveis somam-se: um site típico usa o nível 0 e um theme.css com algumas regras dos níveis 1 e 2. A tabela resume onde fica cada um e o que custa.

Os cinco níveis de personalização
NívelOndeExemploQuando usarO que custa
0course.jsaccentColor: "#0F766E"Cor do curso, logótipo, ordem e nomes das páginas, línguas.Nada: os campos fazem parte do contrato da versão 1 e passam de ano para ano com a pasta.
1theme.css, em :root--uc-radius-lg: 4pxMudar o aspeto de todo o site de uma vez: cantos, letra, cores de estado.Quase nada: os tokens são públicos e estáveis na versão 1. Cada cor nova tem de manter o contraste.
2theme.css.uc-week__title { font-weight: 500; }Mudar uma parte de um componente, ou dar estilo a classes próprias.Depende das classes estáveis de cada componente. Regras sobre classes internas ou sobre a estrutura do HTML gerado podem deixar de funcionar numa versão nova.
3extensions/*.js e .cssUC.define("uc-bst-traversal", …)Algo interativo que o kit não tem: uma animação, um simulador, um exercício especial.Código JavaScript a manter pelo professor: textos nas línguas do curso, acessibilidade, alternativa sem JavaScript.
4As páginas<div class="uc-content">…</div>Conteúdo que já existe em HTML, ou uma página com um aspeto muito próprio.Perde-se o comportamento automático: datas, semana atual, prazos e textos traduzidos ficam à mão.

Uma regra de precedência a ter presente: accentColor do course.js é aplicado diretamente no elemento <html> e ganha sempre a um --uc-color-accent escrito no theme.css. A cor do curso muda-se no course.js; quem a quiser controlar no theme.css tem de apagar o campo accentColor (o modelo traz-o preenchido).

Que nível escolher

Começa-se pelo nível mais baixo e só se sobe quando ele não chega. Um ajuste num nível alto custa mais a manter: um campo no course.js continua a funcionar em todas as versões 1 do kit, uma regra CSS sobre uma classe interna não.

Necessidade e nível recomendado
Para…Nível
Usar a cor da faculdade ou do departamento0: accentColor
Mostrar o logótipo do curso, ou nenhum0: logo
Uma página nova na navegação, ou outro nome para uma página0: pages
Cantos menos redondos, outro tipo de letra, outro verde para "certo"1: tokens
A semana atual com outro destaque, títulos noutro peso2: classes estáveis
Cartões próprios (horários, componentes da nota)2: classes próprias com tokens
Uma animação ou um exercício interativo de uma aula3: componente próprio
Executar código noutro serviço (Codapi próprio, Judge0)Execução de código (níveis 0 e 3)
Aproveitar páginas do site antigo4: HTML livre

Para experimentar cores, cantos e letra sem escrever CSS, o Personalizador de tema mostra o resultado e gera o theme.css.

O que o kit garante

Dentro da versão 1 (kit/v1/) não muda de forma incompatível nada do que está documentado:

  • os campos do course.js;
  • os atributos de cada componente e os tokens;
  • as classes listadas na secção "Personalizar" da página de cada componente e as classes de blocos (uc-card, uc-table…), descritas em Estilos e reunidas em Classes CSS estáveis;
  • a API JavaScript usada pelos componentes próprios (UC.define, UC.Element, UC.t…) e o contrato dos runners.

O resto pode mudar numa versão 1 mais recente: classes que não estão nas tabelas, a estrutura do HTML que os componentes geram, o que está em UC.internal. Quem fixa uma versão exata (kit/v1.0.0/, ver Versão do kit) só vê mudanças quando a troca. A política completa está em Versões.

Um caso real

O site de Estruturas de Dados usa quatro níveis: o course.js com a cor e as páginas, um theme.css com classes próprias escritas só com tokens, um componente próprio para animar percursos em árvores (<uc-bst-traversal>, no guião da aula 10) e páginas com HTML livre dentro de <uc-page>. A página do exemplo Estruturas de Dados mostra o que cada página usa.
